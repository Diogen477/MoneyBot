# MoneyBot — Документация проекта

Telegram-бот для учёта личных расходов. Pyrogram + aiosqlite + matplotlib.

## setup_db.py — Подключение и миграции

### DatabaseConnection (Singleton)
Единственное соединение к БД на всё время работы бота. Защищено `asyncio.Lock` от race condition при конкурентных корутинах.

- `get_connection()` — создаёт или возвращает существующее соединение. Включает WAL и foreign keys.
- `close()` — закрывает соединение.
- `__aenter__` / `__aexit__` — контекстный менеджер. Автоматический `commit()` при успехе, `rollback()` при ошибке.

### init_db()
Создаёт таблицы (`CREATE TABLE IF NOT EXISTS`) и индексы. Запускает миграции:

1. **Объединение дублей категорий** — находит категории, отличающиеся только регистром (Еда/еда), переносит расходы и шаблоны на запись с меньшим id, удаляет дубль.
2. **COLLATE NOCASE индекс** — создаёт уникальный индекс для защиты от будущих дублей на уровне БД.
3. **Нормализация имён трат** — приводит первую букву `expenses.name` к заглавной (`доставка` → `Доставка`).

### Парсер свободного формата (строки 821–885)

| Функция | Описание |
|---|---|
| `extract_numbers_and_words(text)` | Разделяет текст на числа и слова. Убирает суффиксы валют (р, руб, ₸, тг). Десятичная запятая → точка |
| `parse_free_form(text, user_id)` | Парсит свободный ввод. Ищет категорию с начала слов (точное совпадение, case-insensitive). Возвращает `{category, name, price, quantity, total}` |

**Логика parse_free_form:**
1. Извлекает числа и слова
2. Если нет чисел → None
3. Жадный поиск категории: перебирает префиксы слов от длинных к коротким, сравнивает с существующими категориями (case-insensitive)
4. Оставшиеся слова → name
5. Если 2+ числа: price × quantity = total. Если 1 число: total

**Логика handle_expense_entry:**
1. **Точный формат** (есть `,` или `|`):
   - 4 части → Категория, Наименование, Цена, Количество
   - 2 части → Категория, Сумма
   - Если категория не найдена → fuzzy → create
2. **Свободный формат** → `parse_free_form`:
   - Категория найдена → запись сразу
   - Не найдена + есть слова → fuzzy поиск по префиксам → если не нашёл → предложить создать
   - Не найдена + только числа → предложить последнюю категорию

## Замечания по логике и структуре

### Архитектурные проблемы

1. **Монолитный bot.py (~2500 строк)** — вся логика в одном файле. Тяжело поддерживать и тестировать.

2. **Отсутствие слоя абстракции для БД** — SQL-запросы разбросаны по всему коду. Нет единого репозитория/DAO.

3. **Состояние FSM в БД без валидации переходов** — любое состояние может быть установлено откуда угодно, нет схемы допустимых переходов.

4. **Дублирование кода в обработчиках** — `edit_choose_period` и `del_choose_period` почти идентичны (вычисление дат, получение трат, форматирование списка).

5. **Файлы графиков/Excel создаются в текущей директории** — имена содержат user_id, но нет очистки при старте. При краше бота файлы остаются.

### Потенциальные баги

6. **`get_expenses_by_category` ищет только по первому найденному category_id** — если есть дубли категорий (хоть и маловероятно после миграции), часть расходов может не попасть в отчёт.

7. **`get_templates_for_today` проверяет `now.hour == 9`** — но `send_template_reminders` вызывается каждый час cron'ом. Если бот был выключен в 9:00, напоминание пропущено навсегда.

8. **Excel отчёт: категории горизонтально** — при 10+ категориях лист становится нечитаемым. Нет ограничения.

9. **`parse_free_form` не поддерживает многословные категории в свободном формате** если после них нет чисел — весь текст воспринимается как слова.

10. **`send_monthly_comparisons` использует `strftime("%B")` без локали** — названия месяцев будут на английском.

## Предложения по улучшению

### Быстрые улучшения (low effort, high impact)

1. **Бюджеты/лимиты по категориям** — установка месячного лимита. Предупреждение при приближении (80%) и превышении. Самая востребованная фича для финансового бота.

2. **Быстрая запись последней категории** — если пользователь вводит просто число (500), записывать сразу в последнюю категорию без подтверждения. Сейчас каждый раз спрашивает.

3. **Названия месяцев на русском** — в `send_monthly_comparisons` использовать словарь русских названий вместо `strftime("%B")`.

4. **Подтверждение записи при одном сообщении** — показывать inline-кнопку «Отменить» дольше (сейчас нет timeout, но кнопка теряется при следующем вводе).

### Структурные улучшения (medium effort)

5. **Разбить bot.py на модули**: `db/` (репозиторий), `handlers/` (обработчики), `reports/` (графики/Excel), `parsers/` (парсинг ввода), `keyboards.py`, `config.py`.

6. **Экспорт/импорт данных** — возможность скачать все свои данные в CSV/JSON и загрузить обратно.

7. **Статистика и инсайты** — средний расход в день, самая дорогая категория, тренд «растёт/падает» за последние 3 месяца.

8. **Inline-режим** — быстрая запись трат через `@bot сумма категория` из любого чата.

### Продвинутые улучшения (high effort)

9. **Мультивалютность с конвертацией** — запись трат в разных валютах, отчёты в одной базовой валюте по курсу на дату.

10. **Групповой учёт** — совместные расходы (roommates, пары). Каждый видит общую картину и свою долю.

11. **AI-категоризация** — автоматическое определение категории по тексту (на основе истории пользователя) без нечёткого поиска.

12. **Фото чеков** — распознавание суммы с фото чека (OCR) и автоматическая запись.
